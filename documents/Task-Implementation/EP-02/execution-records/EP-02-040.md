## 1. Implementation summary

Defined the provider boundary and the contract every adapter must satisfy.

**Port** (`server/src/integrations/payments/payment-provider.ts`)
- `provisionCollectionAccount` — virtual account for deposits;
- `normaliseDepositEvent` — maps one raw provider event into the neutral deposit shape;
- `initiatePayout` — outbound transfer keyed by an idempotency key;
- `getPaymentStatus` — status query by provider reference;
- `resolveAccountName` — NIBSS-style name enquiry returning the name and last four digits only;
- `PaymentProviderError` with seven stable codes and an explicit `retryable` flag. Only
  `PROVIDER_UNAVAILABLE` and `PROVIDER_TIMEOUT` are retryable by default.

**Fake adapter** (`fake-payment-provider.ts`)
- deterministic, in-memory provider: one account per reference, one payout per idempotency key,
  typed errors for unknown references and malformed payloads;
- never retains a full account number and never logs;
- a test hook can fail the next payout once, for retry tests.

**Contract suite** (`tests/support/payment-provider-contract.ts`)
- provider-neutral: the adapter supplies its own raw deposit payload, bank code and account number;
- covers account idempotency, deposit normalisation and rejection, payout idempotency and conflict,
  status lookup and not-found, name enquiry and last-four-only output, invalid amounts and
  retryability;
- runs against the fake under two provider identities, which is the evidence that a second adapter
  needs no port or schema change.

No VFD type, endpoint, header, credential or envelope exists in the port, the fake, the finance
domain or the ledger. A static test enforces that for the finance and admin service files.

## 4. Design decisions

| Decision | Reason |
|---|---|
| Provider key on every adapter | `finance.provider_references` already stores it; no enum in code. |
| Money remains decimal strings | Matches the ledger and avoids float drift at the boundary. |
| Deposit event is already normalised | The domain must never branch on a vendor envelope. |
| Idempotency key on payout, reference on account | The provider port cannot decide replay semantics for Hivorr; it only must not duplicate an effect. |
| Payout account number passed at call time | It is decrypted for the call only; the port has no storage and the fake keeps only the last four. |
| Name enquiry returns last four only | A full number has no use after matching and must not travel back. |
| Typed error with retryability | Callers must not infer retry from HTTP status inside a vendor body. |
| No webhook signature method | VFD has no documented signature; `EP-02-044` owns the status-verification control and its recorded deviation. |
| Fake lives in `src` | Service tests and later adapter contract tests reuse it; it is not registered as a provider. |
