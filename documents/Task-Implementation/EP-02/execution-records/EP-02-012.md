## 1. Implementation summary

**Scan state machine** (`server/src/modules/profile/domain/evidence.ts`)
- a reference starts `PENDING` and one scan decides it `CLEAN`, `INFECTED` or `FAILED`;
- every decided state is terminal: a rescan is a new reference. A bad object can never be laundered
  into a clean one by a second update;
- only `CLEAN` is usable.

**Database enforcement** (`20261127000600_profile_alter_evidence_scans.sql`)
- `profile.evidence_scan_transition_allowed(from, to)` is the same table in SQL;
- a before-update trigger on `profile.verification_evidence` raises `23514` on any other edge;
- a drift test compares the domain table with the SQL function over all sixteen pairs.

**Submission rule tightened**
- `VerificationLaneService.submit` previously refused only `INFECTED`/`FAILED`; a `PENDING` file was
  accepted. That contradicts the expected outcome ("an unscanned file is unusable"). It now requires
  **every** evidence reference to be `CLEAN`, and still requires at least one.

**Nothing was invented for the blocked parts**
- no bucket name beyond the approved `private-documents`;
- no retention period;
- no scanner integration;
- no public URL and no deletion path.

## 4. Design decisions

| Decision | Reason |
|---|---|
| Terminal scan states | A rescan as a new reference keeps history and prevents laundering. |
| Clean-only submission | The task's outcome says an unscanned file is unusable; accepting `PENDING` was a gap. |
| Rules before transport | The storage adapter and the scanner can be added without re-deciding semantics. |
| No stub scanner | A stub that marks clean would defeat the control it exists to provide. |

## 9. Outstanding issues

- **No upload.** A pre-signed `PUT` needs R2 credentials and the bucket. No evidence can be created
  through the API, so `submit` refuses for want of evidence.
- **No signed read.** Short-lived, object-scoped access and its audit are not built.
- **No scanner.** Nothing moves a reference out of `PENDING`; with the clean-only rule, submissions
  cannot pass until a scanner exists. That is intentional rather than a stub.
- **Retention hold is undefined.** The period is `ARCHITECTURE.md` §16.4 #7 (open); no deletion path
  exists, which matches the task's "no deletion path" but leaves erasure unimplemented.
- **Scan decisions are not audited.** The trigger records the state, not who or what decided it. A
  scanner identity and an audit event belong with the scanner integration.
- **Type and size validation is only a database check.** The upload endpoint must validate before
  issuing a URL; the check constraints are the second line.
