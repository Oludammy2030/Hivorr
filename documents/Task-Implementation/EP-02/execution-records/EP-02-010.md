## 1. Implementation summary

**Lane registry** (`profile.verification_lanes`)
- one row per lane with a display title, description, evidence requirement, sort order and an active
  flag;
- the six approved keys are seeded in display order: `identity`, `kyc`, `trade`, `seller`,
  `logistics`, `business`;
- readable by every authenticated account, writable by none: a lane is added or retired by migration.

**Cases** (`profile.verification_cases`)
- one row per account and lane (`unique (account_id, lane)`), with the seven approved states and an
  optional reason code;
- indexes on `(account_id, state)` and `(lane, state)` so an owner lookup and a queue scan do not
  fall back to a sequential scan;
- the lane is a foreign key, so a lane outside the registry is refused.

**Submissions** (`profile.verification_submissions`)
- one row per review attempt, referencing its case and lane;
- a partial unique index enforces **one active attempt per account and lane**, where active means
  `DRAFT`, `SUBMITTED` or `UNDER_REVIEW`. A rejected or expired attempt frees the slot, which is the
  resubmission path the matrix requires;
- `frozen_at` records the freeze of the subject's identity fields during review; the trigger that
  actually blocks edits is `EP-02-011`'s;
- constraints refuse a decision timestamp without a submission and a freeze outside a reviewing or
  decided state.

**Evidence** (`profile.verification_evidence`)
- a private-object reference only: object key, content type, size, SHA-256 and scan state. No URL,
  no document, no public bucket assumption;
- size is bounded to 25 MiB and the digest must be 64 lowercase hex characters, so a fabricated
  reference cannot be stored;
- `unique (submission_id, object_key)` stops the same object being attached twice.

**Decisions** (`profile.verification_decisions`)
- append-only. `platform.reject_append_only_mutation()` is reused as the update/delete trigger, so
  the rule holds even for a role that somehow gains a grant;
- the API role has `select` only: the verifier writes through a security-definer function in
  `EP-02-015`, not by an insert from the portal;
- `decided_by` is a required user reference, and the reason is required and bounded.

**Access**
- RLS is enabled **and forced** on all five tables; an account reads only its own cases,
  submissions, evidence and decisions;
- an insert must match `platform.current_account_id()`, and a submission insert additionally requires
  that the case belongs to the caller and carries the same lane;
- an evidence insert additionally requires that the submission belongs to the caller;
- the lane registry has a select policy only;
- `hivorr_readonly` receives `select` on all five; no role receives `delete`.

**Not duplicated**
- the KYC tier stays on `identity.accounts.kyc_tier` (`EP-02-014`). This migration adds no tier
  table; the `kyc` lane case is the evidence and review record that will drive the tier. Two tier
  stores would drift.

## 3. Rules

| Situation | Result |
|---|---|
| A lane outside the six approved keys | foreign-key refusal (`23503`) |
| A second case for the same account and lane | unique refusal (`23505`) |
| A second active submission for the same lane | partial-unique refusal (`23505`) |
| A resubmission after `REJECTED` or `EXPIRED` | accepted |
| A submission whose case belongs to another account, or names another lane | RLS refusal (`42501`) |
| An evidence row without a 64-hex digest or above 25 MiB | check refusal (`23514`) |
| Evidence attached to another account's submission | RLS refusal (`42501`) |
| Update or delete of a decision | trigger refusal (`P0001`) |
| An API insert of a decision | privilege refusal (`42501`) |
| A case written for another account | RLS refusal (`42501`) |
| Another account reading a case, submission, evidence or decision | zero rows |

## 4. Design decisions

| Decision | Reason |
|---|---|
| Lane registry as a table, not an enum | A lane carries a title, evidence requirement and order that the portal needs; an enum would push copy into code. |
| `key` is text with a check, not a database enum type | The approved vocabulary lives in `@hivorr/shared`; a database enum would need a migration for every copy change and cannot be diffed against the contract. |
| Partial unique index rather than a `status` column | "Active" is a state set, not a second field that can disagree with `state`. |
| Freeze as a timestamp, enforcement in `EP-02-011` | The column is schema; blocking an edit is a trigger with a transition rule, which belongs to the state machine task. |
| Decisions select-only for the API | A portal insert would bypass the evidence and reason checks the verifier function must apply. |
| Reuse `platform.reject_append_only_mutation()` | One append-only implementation in the platform module; a second copy would drift. |
| No tier table | `identity.accounts.kyc_tier` is the single source; a profile tier table would be a second truth. |

## 9. Outstanding issues

- **The control portal uses a different lane vocabulary.** `admin.verification_reviews.lane`
  constrains `identity | business | address | phone | document`, which does not match the six
  approved lanes. Two vocabularies now coexist. Reconciling them is a control-portal change
  (`CP-019`) and needs a decision on the mapping, so it was not attempted here.
- **Business uniqueness is per account, not per business.** The matrix requires one active submission
  across a business's members. There is no business entity yet, so the index cannot express it; it
  becomes possible when the business lane and membership model land.
- **Freeze is recorded, not enforced.** `frozen_at` exists; the trigger that blocks identity edits
  during review belongs to `EP-02-011`.
- **The transition graph is not enforced.** Any approved state can currently be written. `EP-02-011`
  owns the allowed transitions.
- **No evidence scanning.** `scan_state` defaults to `PENDING`; nothing advances it until
  `EP-02-012`.
- **No audit events from this task.** State changes and decisions are audited by `EP-02-011`/`015`.
- **Retention is not decided.** Evidence references may outlive a deletion request; the retention
  decision (`ARCHITECTURE.md` §16.4 #7) is still open.
