## 1. Implementation summary

**Recipient and source enquiries** (`server/src/integrations/vfd/account-name.ts`)
- `enquireRecipient` returns the documented name, client id, account id, BVN and bank name alongside
  the last four digits; `resolveAccountName` remains the neutral port method;
- `enquireSource` calls the documented `/account/enquiry` endpoint and returns the sender profile
  (`clientId`, `client`, `accountId`) a transfer must echo back;
- a recipient or source response naming a different account is refused.

**Payout adapter** (`server/src/integrations/vfd/payouts.ts`)
- implements the payout slice of `PaymentProvider`: `initiatePayout`, `getPaymentStatus` and
  `resolveAccountName`;
- validates reference, NGN-only currency, amount, bank code, ten-digit account number and account name;
- queries the source wallet and the beneficiary, then builds the documented `/transfer` payload with
  `transferType=inter`, `toClientId`, `toSession`, `toAccount`, `toBank`, `fromAccount`, `fromClientId`,
  `fromClient`, `fromSavingsId`, optional beneficiary BVN, signature, amount, remark and reference;
- signs with `VfdSha512TransferSigner`: the vendor documents `SHA512(fromAccount + toAccount)` and its
  published sample value is exactly that digest. The signer can still be overridden;
- replays one result per idempotency key and refuses a reused key with a different fingerprint;
- maps `98` to `PROVIDER_DUPLICATE`, `02` to `PROVIDER_AUTH_FAILED`, `00` to a pending result, the
  documented pending codes to `processing`, and other codes to a failed result with `VFD_<code>` and a
  sanitised message;
- `getPaymentStatus` calls the documented `/transactions?reference=` endpoint, maps success/pending/
  failure codes, normalises the amount and parses the documented timestamp;
- `401`/`403` invalidates the token; `429`/`5xx`/timeouts retry within the configured budget; no
  account number, credential or response body is logged.

**Configuration and wiring**
- `VFD_SOURCE_ACCOUNT` is an optional, secret-classified ten-digit wallet account. The adapter refuses
  to send while it is unset;
- `VFD_PAYOUTS` is a Nest provider built from `VFD_AUTH`, `VFD_ACCOUNT_NAME`, the configured source
  account and the default SHA-512 signer, so `EP-02-053` can inject the payout slice.

**Vendor facts resolved from the committed documents**- the transfer signature is unkeyed `SHA512(fromAccount + toAccount)` hex; the sample signature in
  `VFD_WALLET.md` §9.2 reproduces exactly, so no secret is assumed;
- the source profile comes from `/account/enquiry`; only the source account number is configuration;
- the transfer amount unit is still not stated. The canonical `numeric(20,4)` string is sent unchanged
  and the ambiguity is recorded for `EP-02-045`;
- only `NGN` is accepted, because the documented transfer payload has no currency field.

## 1a. Provider switch — 2026-11-26

**Founder decision.** Paystack is the active provider for fast integration; VFD is paused behind the
same provider port. The control panel switches provider and mode; test/live secrets remain in the
deployment secret store and are never entered or returned by the portal.

**Paystack adapter** (`server/src/integrations/paystack/payouts.ts`)
- resolves a name via `GET /bank/resolve`;
- creates a NUBAN recipient and initiates a single transfer via `POST /transferrecipient` and
  `POST /transfer`;
- converts NGN to kobo and refuses sub-kobo precision instead of rounding;
- verifies a transfer via `GET /transfer/verify/:reference`;
- maps failures, duplicates, auth, timeout and availability to the provider-neutral codes;
- fails closed when the active mode has no key; no key, account number or response body is logged.

**Provider switch**
- `platform.payment_provider_setting` is a single-row, secret-free setting (`paystack|vfd`,
  `test|live`);
- `platform.get_payment_provider` / `set_payment_provider` are audited security-definer functions;
  the write requires `admin.configuration.write`;
- `PaymentProviderRouter` reads the active setting per call, so a switch applies without a redeploy;
- `PayoutExecutionService` records the concrete provider from the result, not from the router.

**Control panel**
- `GET`/`POST /v1/control/payments/provider`; the response reports whether each provider/mode key is
  configured, never the key itself;
- a Payments page in the control portal switches provider/mode and shows configured/missing badges;
- no secret is accepted by the API or rendered in the browser.

**Collections and deposit posting**
- `PaystackCollectionsClient` creates a customer and dedicated virtual account, normalises
  `charge.success`, and verifies a transaction before any credit.
- `finance.collection_accounts` stores one DVA per account with the owner user; no provider secret.
- `DepositPostingService` verifies the webhook signature and the transaction, records the provider
  reference idempotently, applies the CBN deposit cap/hold, and posts debit wallet / credit
  `platform_clearing` in one transaction.
- `POST /v1/webhooks/paystack` is public but signature-authenticated; `GET`/`POST
  /v1/wallet/collection-account` expose the DVA to its owner.

**Paused VFD**
- VFD adapters remain in place and selectable; VFD mode must match `VFD_MODE`.
- Paystack webhook raw storage and a full reconciliation path remain for `EP-02-044`/`055`.

## 3. Mapping rules

| Situation | Result |
|---|---|
| `00` direct transfer | `pending` result with the vendor `txnId`/session id |
| `01`, `09`, `25`, `94`, `96`, `500` | `processing` result |
| `98` | `PROVIDER_DUPLICATE` |
| `02` direct transfer | `PROVIDER_AUTH_FAILED` (the vendor also lists `02` as pending in the status table; the failure table wins) |
| Other codes | `failed` result with `VFD_<code>` |
| TSQ `00`/`26` | `paid` |
| TSQ `01`/`02`/`09`/`25`/`94`/`96`/`500` | `pending` |
| TSQ other codes | `failed` |
| TSQ `108` | `PROVIDER_NOT_FOUND` |
| Missing source/signer | `PROVIDER_AUTH_FAILED`, no fetch |
| Non-NGN currency | `PROVIDER_INVALID_PAYLOAD`, no fetch |
| Beneficiary lacks `clientId`/`accountId` | `PROVIDER_INVALID_PAYLOAD`, no transfer fetch |
| Reused idempotency key, different payload | `PROVIDER_DUPLICATE`, no second transfer |

## 4. Design decisions

| Decision | Reason |
|---|---|
| Payout slice of `PaymentProvider`, not a second port | `Pick<PaymentProvider, ...>` reuses the approved vocabulary; the collections half is `EP-02-042` and a composition will satisfy the full interface. |
| Default signer is the documented SHA-512 digest | The vendor page states the formula and its sample signature reproduces exactly; a secret would contradict the published vector. |
| Source profile read from `/account/enquiry` | The documented flow obtains `fromClientId`, `fromClient` and `fromSavingsId` there; storing a second copy would drift. |
| Only the source account number is configuration | It is the one value the enquiry cannot discover; it is secret-classified and optional. |
| No live call | No sandbox credential is present in this environment. |
| NGN only | The transfer payload has no currency field; accepting another currency would send an ambiguous amount. |
| Amount sent as the canonical decimal | The vendor does not state the unit; the value is not silently converted to kobo. |
| `inter` for every bank code | Same ruling as `EP-02-050`; the recipient endpoint does not enumerate transfer types. |
| Retry a timed-out POST with the same reference | The vendor rejects a duplicate reference (`98`); the workflow must treat that as an unknown outcome and reconcile via TSQ. |
| Status query currency is `NGN` | The documented TSQ response has no currency field; the adapter refuses any other payout currency. |
| Date parsed as UTC | The documented timestamp has no zone; the ledger is UTC and the ambiguity is recorded. |

## 9. Outstanding issues

- **Source account is not provisioned here.** `VFD_SOURCE_ACCOUNT` must be set from the deployment
  secret store before a live VFD payout. The adapter refuses to send while it is unset.
- **Paystack live key is not in this environment.** The control page shows it as missing; the adapter
  fails closed for the selected mode until the deployment secret store provides it.
- **Paystack collections and webhook intake are not built.** `EP-02-042`/`044` remain pending; VFD is
  paused but selectable.
- **Amount unit is unconfirmed.** The vendor sample shows an integer while the status sample has
  decimals; the adapter sends the canonical decimal unchanged.
- **Bank list is not implemented.** `GET /bank` is documented as an operation but publishes no
  parameters, response fields or error shape. A parser would be a guess.
- **No sandbox certification.** `EP-02-045` owns it; a credential and source account are required.
- **`EP-02-053` is not built.** It owns the workflow, dual control, durable idempotency and the
  composition with the collections half (`042`).
- **Retried POST ambiguity.** A timeout after the vendor applied the transfer returns `98` on retry;
  the workflow must treat that as unknown and reconcile via TSQ.
- **VFD written licence scope (BD-D11) remains open.**
