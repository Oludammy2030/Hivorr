## 1. Implementation summary

**Configuration** (`server/src/config.ts`, contract, template, topology)
- adds `PAYOUT_ENCRYPTION_KEY`, `PAYOUT_ENCRYPTION_KEY_ID`, `PAYOUT_FINGERPRINT_KEY` and
  `PAYOUT_ACCOUNT_MAX_ACTIVE`;
- the two keys must each be 32 bytes encoded as base64, must be different, and are required in staging
  and production; a partial pair is a configuration error;
- an empty destination cap is treated as unset. Unset means binding is refused, not defaulted. The
  approved number is still **[OPEN]**.

**Encryption** (`server/src/modules/finance/payout-account-crypto.ts`)
- AES-256-GCM envelope with a format byte, 12-byte nonce and 16-byte tag; the key version is stored in
  `encryption_key_id` beside the ciphertext;
- a separate HMAC-SHA256 key produces the 64-hex fingerprint used for uniqueness and lookup;
- the only account-number material returned for display is the last four digits;
- account-name comparison case-folds, normalises NFKC and collapses whitespace, but does not strip
  titles or reorder names.

**Provider name enquiry** (`server/src/integrations/vfd/account-name.ts`)
- calls the documented `GET /transfer/recipient?accountNo=&bank=&transfer_type=` endpoint through the
  existing `VfdAuthClient`;
- sends `transfer_type=inter` for every bank code because the vendor page does not enumerate the
  values for this endpoint; the transfer payload documents `intra`/`inter`;
- maps failures to the provider-neutral codes and never logs or echoes the account number.

**Identity** (`server/src/modules/identity/identity.service.ts`)
- adds `getAccountLegalName(accountId, userId)`, so finance compares against `identity.accounts`
  without importing another module's repository.

**Service** (`server/src/modules/finance/payout-account.service.ts`)
- `bind` requires `tier_1` or above, a configured destination cap and both keys, a non-empty verified
  legal name, and a provider name that matches it;
- a mismatch is refused before any row is written;
- the insert stores only a `verified` row with ciphertext, key id, last four and fingerprint;
- `list` projects only masked numbers and no ciphertext;
- `disable` is the only update, requires a reason, and writes an audit record;
- cap accounting runs under a transaction-scoped advisory lock per owner.

**Database** (`20261123000100_finance_add_payout_account_write_path.sql`)
- grants insert/update and owner-scoped insert/update policies on `finance.payout_accounts`;
- a trigger refuses an insert that is not `verified`, refuses any update other than `-> disabled`, and
  refuses changing a bank field once bound;
- a second trigger refuses delete;
- no balance, payout or reconciliation write path was added.

## 3. Denial rules

| Situation | Result |
|---|---|
| Tier below `tier_1` or missing | `KYC_REQUIRED` (403) |
| Destination cap unset | `SERVICE_UNAVAILABLE` (503) |
| Payout keys unset | `SERVICE_UNAVAILABLE` (503) |
| Account has no verified legal name | `KYC_REQUIRED` (403) |
| Resolved name differs from the legal name | `VALIDATION_FAILED` (422) |
| Cap already reached | `LIMIT_EXCEEDED` (409) |
| Same destination bound twice | `CONFLICT` (409) |
| Provider enquiry fails | `PROVIDER_ERROR` (502), vendor detail redacted |
| Disable without a reason | `VALIDATION_FAILED` (400) |
| Disable a destination the owner does not hold | `NOT_FOUND` (404) |

At the database layer, the trigger independently refuses a non-verified insert, a status change other
than disable, a bank-field rewrite, and delete.

## 4. Design decisions

| Decision | Reason |
|---|---|
| Cap is configuration and unset refuses binding | The approved destination count is not decided; inventing one would create policy. Recorded as **[OPEN]**. |
| Two distinct 32-byte keys | One key for confidentiality and one for the uniqueness fingerprint limits the blast radius of a key leak. |
| Key version stored beside ciphertext | Allows rotation without rewriting the schema or losing which key opened a row. |
| Provider call before the write transaction | A network call must not hold a database transaction; the resolved name is checked first, then the row is written atomically. |
| Insert only as `verified` | This increment only knows the name-matched path; a pending path would be an untested state. |
| Update only to `disabled` | Bank details must be immutable once bound; a correction is a new destination. |
| Advisory lock on the owner | Two concurrent binds must not both pass the cap check. |
| No HTTP endpoint yet | No trusted KYC tier or legal-name source exists until `EP-02-014`; the service accepts the tier at the session boundary, mirroring `EP-02-035`. |
| `transfer_type=inter` | The recipient endpoint does not enumerate values; `inter` covers any Nigerian bank. The ambiguity is recorded rather than guessed per bank. |
