## 1. Implementation summary

Added a typed dispute record behind the existing admin case spine, with no outcome policy.

**Schema** (`20261119000100_admin_create_disputes.sql`)
- `admin.disputes` belongs to the admin module, as the database rules and the schema comment already
  state ("Admin roles, review queues, moderation, configuration, audit access, disputes");
- it references a case (one dispute per case), the opening and respondent accounts, the activity and
  record, the currency and claimed amount, and an optional escrow reservation;
- statuses are `OPENED`, `UNDER_REVIEW`, `AWAITING_EVIDENCE`. There is no resolved, refunded,
  rejected or closed state;
- the table has RLS enabled, forced, and no grant to any application role. Every read and write goes
  through permission-checked security-definer functions.

**Functions**
- `admin.open_dispute` — requires `admin.dispute.resolve` or `admin.case.assign`, a reason, a valid
  activity/currency/amount and an existing case; records `dispute_opened` on the case timeline;
- `admin.dispute_view`, `admin.list_disputes` — require `admin.case.read` or `admin.dispute.resolve`;
- `admin.set_dispute_status` — allows only procedural moves between the three states; same-state is a
  no-op; anything else is refused;
- `admin.record_dispute_evidence_access` — resolves the dispute's case, requires the evidence to
  belong to that case (a mismatch is reported as not found), then reuses the CP-017
  `record_evidence_access` so a case event is written.

**Service** (`server/src/modules/admin/dispute.service.ts`)
- open, list, get, status change, evidence metadata and evidence-access recording;
- each write appends a platform audit row in the same transaction:
  `admin.dispute_opened`, `admin.dispute_status_changed`, `admin.dispute_evidence_accessed`;
- evidence metadata is read through the existing `EvidenceService`, not a second query.

**Shared contract**
- `DISPUTE_STATUSES`, `disputeStatusSchema` and `disputeSchema` added to `@hivorr/shared`.

## 3. Design decisions

| Decision | Reason |
|---|---|
| Table in `admin`, not `finance` | The database rules and `ARCHITECTURE.md` §9.13 assign disputes to administrative services. The task anticipated a finance migration; the approved ownership wins and is recorded here. |
| No table grant; functions only | The rest of the case spine works this way, and every access is permission-checked in one place. |
| Procedural statuses only | Resolved/refunded/closed are outcomes and require BD-D03. |
| One dispute per case | A second typed record for the same case would be ambiguous; a correction is a new case or a case event. |
| Evidence lives on the case | CP-017 already owns evidence metadata and access recording; a second evidence table would duplicate the control. |
| Evidence outside the dispute's case reads as not found | It does not confirm that another case's evidence exists. |
| Claimed amount is a claim, not a balance | It is stored as `numeric(20,4)` with its currency and is never adjusted by this task. |
| No case-type requirement | The case spine defines the type; requiring `dispute` here would duplicate that rule and block `financial_exception` cases. |
