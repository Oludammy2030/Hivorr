> **Recorded deviation (DoD-01).** The task requires every event to be stored raw before
> interpretation and processed asynchronously. The built handler verifies the signature, verifies the
> transaction with Paystack, and posts inside the request. Nothing is stored raw, and no queue is

> acknowledgement cannot be replayed from a stored payload. It is recorded here for the reviewer.

## 1. Implementation summary

**Endpoint** (`server/src/api/paystack-webhook.controller.ts`)
- `POST /v1/webhooks/paystack` is public by audience but authenticated by the HMAC-SHA512 signature
  over the raw body;
- the active provider setting is read first: while VFD is active the handler acknowledges and does
  nothing (`provider_paused`), so a Paystack event cannot change a VFD-operated ledger;
- the active mode selects the key; an unconfigured key is `SERVICE_UNAVAILABLE`, never a silent skip.

**Handler** (`server/src/modules/finance/deposit-posting.service.ts`)
- signature verified with `verifyPaystackSignature` in constant time before parsing;
- a body that is not JSON is `VALIDATION_FAILED`; a non-charge event is acknowledged and ignored;
- a non-`received` event is acknowledged and ignored;
- `PaystackCollectionsClient.verifyTransaction` is called and the verified status decides whether to
  post. The webhook is a trigger, never the authority;
- the collection account is resolved from the verified transaction's collection reference; an
  unknown account is acknowledged and ignored (`collection_not_found`) so the provider does not retry
  forever;
- posting is delegated to `EP-02-052`, which is transactional and idempotent.

**Deduplication**
- the stable identifier is `(provider, provider_reference)`, enforced by a unique constraint on
  `finance.provider_references`;
- a replay returns `replayed` without a second ledger entry; a reused reference describing a
  different movement is `CONFLICT`.

## 3. Rules

| Situation | Result |
|---|---|
| Active provider is VFD | `accepted: false`, `provider_paused`; no parse, no post |
| Active mode has no key | `SERVICE_UNAVAILABLE` (503) |
| Signature does not match the body | `UNAUTHENTICATED` (401); no parse |
| Signed body is not JSON | `VALIDATION_FAILED` (400) |
| Event is not `charge.success` | `accepted: false`, `not_a_deposit` |
| Event status is not `received` | `accepted: true`, `not_received`; no post |
| Paystack verification returns non-`received` | `accepted: true`, `not_verified`; no post |
| Collection account unknown | `accepted: true`, `collection_not_found`; no post |
| Verified deposit within the tier cap | posted, `posted: true` |
| Verified deposit over the tier cap | recorded failed, `kyc_upgrade_required`, no credit |

## 4. Design decisions

| Decision | Reason |
|---|---|
| Synchronous processing | The posting path is a single short transaction; a queue would add a failure mode before `EP-02-055` owns retries and reconciliation. The deviation is recorded rather than implied. |
| Verify before posting | A webhook body is attacker-reachable even when signed; the transaction query is the authority for amount, currency and status. |
| Ignore unknown collection accounts | An unowned credit cannot be posted; acknowledging prevents an infinite provider retry. |
| Provider switch checked first | A paused provider must not write to the ledger, even for a valid signature. |
| Provider reference as the dedupe key | It is the only identifier Paystack guarantees stable across retries. |
| No raw payload stored | Would require a storage decision and retention period; `ARCHITECTURE.md` §16.4 #7 is open. Recorded as the gap. |

## 9. Outstanding issues

- **No raw-payload store.** A lost event cannot be replayed. Retention is `ARCHITECTURE.md` §16.4 #7
  (open), so no storage was invented.
- **No asynchronous processing.** The outbox is not used; posting happens inside the request.
- **VFD intake does not exist.** VFD publishes no webhook signature; a poll-and-reconcile design is
  the realistic path and belongs to `EP-02-045`/`055`.
- **Payer-name matching (`EP-02-051`) is not applied.** Matching is by collection account only.
- **No sandbox certification.** No Paystack test key is present.
