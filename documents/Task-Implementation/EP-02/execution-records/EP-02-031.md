## 1. Implementation summary

Added the only write path into the ledger, in two layers.

**Pure domain (`server/src/modules/finance/ledger.ts`)**
- validates an entry's kind, reference, currency, idempotency key, activity attribution and posting count;
- converts every amount to integer minor units (1/10,000) with `moneyToMinorUnits`; floats never enter the calculation;
- rejects zero, negative, over-precise (more than four decimals) and over-range (more than 16 integer digits) amounts;
- rejects a posting whose currency differs from the entry;
- requires at least one debit and one credit and an exact zero sum;
- validates a reversal as an exact inversion of the target entry — same accounts, amounts and currency, opposite direction, same posting count;
- derives per-account debit, credit and net effects without reading or storing a balance.

**Transactional writer (`server/src/modules/finance/ledger.service.ts`)**
- one transaction holds the reversal lookup, the entry insert, all postings and the audit record;
- postings are one parameterised multi-row insert, capped at 100;
- audit action `finance.entry_posted` is written through the platform module in the same transaction;
- validation and SQLSTATE failures map to stable API errors; no update, delete or raw-balance method exists.

**Write path (`supabase/migrations/20261118000200_finance_add_ledger_write_path.sql`)**
- grants insert on `journal_entries` and `postings` to `hivorr_api` only;
- insert policies require a transaction identity but do not require the caller to own every posting, because a transfer legitimately touches two accounts; authorisation remains the service layer's responsibility;
- a unique partial index allows an entry to be reversed once;
- the entry select policy now also admits an entry the actor recorded, because an `insert … returning` is checked against the select policy before the postings exist.

## 3. Design decisions

| Decision | Reason |
|---|---|
| Integer minor units, not floats | 0.1 + 0.2 must be 0.3 exactly; `numeric(20,4)` is mirrored in `bigint`. |
| Canonical amount strings | The writer persists four decimals while accepting `"100.1"`; both forms compare equal. |
| Exact reversal, same posting count | A correction restates the whole entry; a partial change is a new adjustment entry, not a reversal. |
| One reversal per entry | A second full reversal would double-correct; the unique index makes that unrepresentable. |
| No stored effect | `deriveAccountEffects` is returned to the caller, not written to an account row. |
| Audit in the same transaction | A financial record without its audit row would be unreconstructable. |
| Insert policy requires context, not ownership | A deposit credits a wallet and debits clearing; an escrow release touches two parties. Requiring ownership would make the approved flows impossible. |
| Creator can read their entry | Required for `insert … returning`; it is the same visibility the posting rule grants once postings exist. |
| No HTTP endpoint | The task is the engine; deposits, payouts and API exposure are `EP-02-052`/`053` and later. |
| No account provisioning | Deliberately absent; `EP-02-032`/`035` own wallet creation and gating. |

## 4. Shared-contract reconciliation

`EP-02-002` had written uppercase escrow and payout states and a `provider` owner type. The
`EP-02-030` schema uses the database values. Two vocabularies cannot both be authoritative, so this
task aligned the shared contract to the implemented schema:

| Contract | Before | After |
|---|---|---|
| `ESCROW_STATES` | `PENDING, HELD, RELEASED, REFUNDED, DISPUTED` | `held, released, refunded, disputed, cancelled` |
| `PAYOUT_ACCOUNT_STATES` | `PENDING, VERIFIED, REJECTED, DISABLED` | `pending, verified, rejected, disabled` |
| `LedgerAccount.ownerType` | `account, platform, provider` | `account, activity, platform` |
| `JournalEntry.kind` | free string | `JOURNAL_ENTRY_KINDS`, shared with the database check |
| `JournalEntry.reference` | 1–120 characters | 3–64 characters, matching the database |

`journalEntrySchema` now also enforces a balanced entry and one currency. Money helpers live in
`@hivorr/shared` so the contract and the engine use one representation.
