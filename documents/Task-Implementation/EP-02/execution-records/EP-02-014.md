## 1. Implementation summary

**Schema** (`20261123000400_identity_add_kyc_tier.sql`)
- `identity.accounts.kyc_tier` with `tier_0` default and a check limited to `tier_0`/`tier_1`;
- `kyc_tier_updated_at`;
- `identity.set_kyc_tier(actor, account, tier, reason)`, a security-definer function that requires
  `admin.verification.review`, validates the tier and reason, and returns the updated row;
- no higher tier, threshold or verification-vendor behaviour is invented.

**Tier-based withdrawal limit** (`20261123000500_finance_seed_cbn_withdrawal_limit.sql`)
- `tier_1` is mapped to CBN Level 2 and seeded with the CBN 2013 Level 2 mobile-banking daily
  withdrawal limit, ₦100,000/day;
- the row lives in `finance.limits` as `limit_type='withdrawal'`, `period='daily'`, `currency='NGN'`;
- the self-service withdrawal uses the `withdrawal` limit type, so the cap is applied by the existing
  effective-dated limit engine;
- `tier_0` is denied before the limit check; a later decision changes the cap with a new row, not a
  code change.

**Capability input**
- `buildAccessContext` and `loadAccessContext` now carry `kycTier`, read from the account;
- `getSession` returns `kycTier` and composes capabilities with it, so `wallet.withdraw` can become
  available when the account is `tier_1`;
- the current-session contract includes `kycTier`.

**Assignment**
- `IdentityService.setKycTier` validates the tier and reason, calls the database function and audits
  `identity.kyc_tier_changed` with the previous and new tier;
- `POST /v1/control/accounts/{id}/kyc-tier` exposes the verifier action; the database re-checks
  `admin.verification.review`;
- the action is independent of activity lanes.

**Self-service withdrawal**
- `POST /v1/wallet/withdrawals` and `GET /v1/wallet/payouts` are now exposed (`EP-02-053`);
- the controller passes the session tier to the request/execution services; no tier is inferred from
  the request body.

## 8. Outstanding issues

- The seeded `tier_1` daily cap is NGN 100,000 (CBN 2013 Level 2 mobile banking). Counsel/founder must
  confirm that this is the applicable CBN framework for Hivorr before production.
- Verification decisions (`EP-02-015`) must set the tier automatically; today a verifier assigns it.
- No tier history table; the audit log is the history.
- DB integration and RLS tests must run in CI.
- Configuration-driven tier definitions are not implemented; only the two approved values exist.
