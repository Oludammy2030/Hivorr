## 1. Implementation summary

Added the first EP-02 shared vocabulary to `@hivorr/shared`:

- six verification lanes, seven lane states, KYC tiers and decision/evidence shapes;
- ledger account kinds, posting directions, escrow states, payout-account/payout states, deposit-match states, money and currency shapes, wallet view, provider reference and escrow reservation;
- stable API error codes for verification, KYC, payout account, insufficient funds, limits, duplicate requests and provider failures.

The server capability context now consumes `VerificationState` rather than a boolean lane flag. A capability that requires a lane is allowed only when that lane is `APPROVED`.
