## 1. Implementation summary

**Token client** (`server/src/integrations/vfd/auth.ts`)
- requests a finite `validityTime` from configuration; it never sends the vendor's non-expiring `-1`;
- caches the token until one minute before expiry and shares a single refresh between concurrent
  callers;
- bounds every attempt with a timeout and the whole call with a configured retry count;
- retries only `429`/`5xx` and transport timeouts; a `401`/`403` or a malformed envelope fails
  immediately;
- maps failures to `PaymentProviderError` codes;
- never includes the key, secret, token or response body in an error message;
- fails closed when the credential pair is absent;
- selects the documented test or live token URL from the mode.

**Configuration**
- `VFD_MODE` (`test` or `live`, default `test`), `VFD_CONSUMER_KEY`, `VFD_CONSUMER_SECRET`,
  validity, timeout, retry count and delay;
- **live mode is refused outside production**, and requires both credential values;
- a key without a secret (or the reverse) is refused;
- `VFD_TOKEN_VALIDITY_MINUTES` cannot be `-1`; the range is 5–60 minutes;
- every key is in `.env.example` and the configuration contract.

**Wiring**
- `VFD_AUTH` is a Nest provider backed by `apiConfig.vfd`;
- an opt-in integration test runs against the VFD sandbox only when `VFD_CONSUMER_KEY` and
  `VFD_CONSUMER_SECRET` are present in the local environment. It never prints the token.

## 3. Security and resilience decisions

| Decision | Reason |
|---|---|
| Never request `-1` | A non-expiring token grants indefinite access if leaked. |
| Cache minus 60 seconds, minimum 30 seconds | A token that expires mid-request is a failed payment. |
| Single-flight refresh | Concurrent requests must not stampede the token endpoint. |
| Retry only temporary failures | Retrying a rejected credential can lock the account; retrying a timeout cannot create a second effect because this is a read-only token call. |
| Errors carry no vendor body | The body can carry identifiers; the message is for operators, not a log of the response. |
| Live mode only in production | A staging switch must never move real money. |
| Test mode default everywhere | The safe mode is the default; live is an explicit act. |
| Credentials from the secret store | The repository and the contract hold names, never values. |
