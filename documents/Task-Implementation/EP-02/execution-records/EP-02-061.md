## 1. Implementation summary

**Screen** (`src/features/wallet/screens.tsx`)
- four derived figures — available, pending, withdrawable, total — read from
  `GET /v1/wallet/balance`. Nothing is computed in the browser; an empty wallet shows the server's
  zeros;
- deposit account card: shows the DVA number, account name, bank and currency when present, and
  offers provisioning otherwise. The number is the provider-issued one; no secret is displayed;
- withdrawal form: payout-account select (verified accounts only), amount field, submit. The amount is
  sent as entered, validated by the server; the screen never applies a limit or a balance check;
- payout accounts: list with masked number, holder name and state, a bind form (bank code, bank name,
  account number) and a disable action. Binding errors from the server are surfaced verbatim;
- recent activity: the latest statement page (entry kind, timestamp, reference, signed amount), with
  a refresh action; the list reloads after a deposit account, withdrawal or binding change.

**Routing**
- `wallet` is registered in `packages/app-shell/src/route-manifest.ts` and rendered by
  `src/slice-main.tsx`; the activity switcher links to `/wallet`;
- the route is auth-required and not indexable, per the shared route definition.

**Presentation rules**
- colours, radii, shadows and type come from `@hivorr/design` tokens; no new hex, font or radius is
  introduced;
- credits use the success colour, debits the ink colour, status uses a pill;
- a `tier_0` account is blocked by the API, and the API's message is shown in the alert region.

## 3. Rules

| Situation | Result |
|---|---|
| Signed out | the screen offers a sign-in link; no wallet data is requested |
| Empty wallet | four zero figures, no fabricated activity |
| No deposit account | provisioning action shown; no account number invented |
| No verified payout account | withdrawal disabled with an explanation, not a failing submit |
| Server refusal (KYC, limit, balance, destination) | the API message is displayed in the alert region |
| Binding with a mismatched name | the server refusal is displayed; the account is not listed |
| Statement empty | an explanatory empty state, not a blank card |

## 4. Design decisions

| Decision | Reason |
|---|---|
| Connected slice, not a prototype edit | `AGENTS.md` forbids changing the prototype; the slice is the functional surface. |
| Server figures only | Client-side financial calculation is forbidden; the screen renders what the API returns. |
| Amount sent unvalidated | The limit, balance and currency checks belong to the service layer, which re-checks them. |
| Masked account numbers only | The full number is never returned by the payout-account API. |
| Statement limited to the first page | The endpoint supports a keyset cursor; pagination UI is not built. |

## 9. Outstanding issues

- **No dedicated `tier_0` state.** The gate is enforced by the API; the screen should explain the
  requirement before the user attempts a withdrawal.
- **No statement pagination.** The endpoint supports `before`/`beforeId`; the screen shows one page.
- **No component tests.** Behaviour is covered by build, route and visual gates only.
- **Responsive verification belongs to `EP-02-063`.** The layout uses a fluid grid but 375/768/1280
  is not evidenced here.
- **Prototype parity is partial.** Saved cards, statement filters and statement detail screens in the
  prototype are not ported.
