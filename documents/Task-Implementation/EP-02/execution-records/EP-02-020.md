## 1. Implementation summary

Created the `platform` taxonomy registry for the two approved taxonomies:

- **Profession:** Industry → Profession.
- **Product:** vertical → category → subcategory → product type → attributes.

The migration adds the node and attribute tables, sibling/root uniqueness, level/parent validation, cycle protection, typed attribute definitions, RLS read policies and read-only grants. The pure domain module validates the same rules before persistence.

## 3. Schema and controls

| Control | Implementation |
|---|---|
| Taxonomy kind | `profession` or `product` |
| Level set | `industry`, `profession`, `vertical`, `category`, `subcategory`, `product_type` |
| Root rule | Only `industry` and `vertical` may have no parent |
| Parent rule | Trigger enforces the exact parent level and matching taxonomy |
| Sibling uniqueness | Partial unique indexes for roots and non-root siblings |
| Cycle protection | Recursive ancestor check in the trigger; pure `createsCycle` helper |
| Attributes | Typed (`text`, `number`, `boolean`, `enum`, `date`); only on `profession` or `product_type` |
| Enum attributes | Must carry at least one value |
| RLS | Enabled; select policy for `hivorr_api` and `hivorr_readonly` |
| Write grants | API role has **no** insert/update/delete grant; admin writes arrive in EP-02-021 |
| Version metadata | `version`, `effective_from`, `effective_to`, `is_active` |
