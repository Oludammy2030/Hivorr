## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| One rule table for the full matrix | Makes authorisation data, not scattered `if` statements | Yes |
| Stable deny reasons | Clients and tests can distinguish the failure class | Yes |
| Verification/KYC/admin/member inputs optional | EP-01 does not own them; absence denies | Yes |
| Admin roles separate from grants | The grant table stays unchanged; admin roles are a different axis | Yes |
| `tier_0` vs `tier_1` only | The ladder is OPEN; inventing tiers would be a policy decision | Yes |
| Full shared ID list | One vocabulary for API and clients | Yes |
