## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| Tokens are `var(--…)` references | `theme.css` remains the only place a colour value is defined | Yes |
| Extract only Button, TextField, Pill | The slice uses these; extracting shells/dialogs now would be speculative | Yes |
| Parity against the live prototype | Stronger than a self-referential baseline; proves token fidelity | Yes |
| Fixed, integer-aligned wrapper in the parity check | Removes subpixel placement noise so the comparison measures style, not position | Yes |
| Test-only gallery under `visual/` | No production entry, no bundle cost | Yes |
| `TextField` label association | Accessibility without changing rendering | Yes |
| `Pill` takes a tone, not arbitrary colours | Prevents raw colour values entering the package | Yes |
| React peer dependency | The package renders components; the host supplies React | Yes |

Two defects were caught during bring-up:

1. **Subpixel placement noise.** Comparing element screenshots in their natural layout produced
   differences from fractional positions, not styles. The parity check now moves both elements into
   the same fixed, integer-aligned wrapper before measuring. Computed styles and pixels then match
   exactly.
2. **Formatter bug (recurring).** oxfmt collapses a single-line inline type with multiple properties
   (`{ padding: string; fontSize: number }` → `{ padding: string fontSize: number }`). Both cases were
   replaced with named interfaces.
