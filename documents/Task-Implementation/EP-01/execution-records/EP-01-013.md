## 1. Implementation summary

The API contract is now a generated artifact, not a document:

| Artifact | Source | Result |
|---|---|---|
| `openapi/openapi.json` | `server/src/openapi/build.ts` | OpenAPI 3.1.0, 17 paths, 20 operations |
| `packages/api-client/src/index.ts` | `server/src/openapi/client.ts` | Typed client with 20 methods |
| Request schemas | `server/src/contracts/schemas.ts` | Used by controllers and the generator |
| Route coverage | `server/src/openapi/scan.ts` | Compares Nest metadata with the registry |

The generator uses `zod`'s `toJSONSchema` and a small JSON-Schema-to-TypeScript emitter. No
dependency was added. Every operation declares its audience, responses, security and path
parameters; four host-only cookie schemes document the four portals.

`pnpm openapi:check` regenerates both committed outputs and fails on a diff, and the existing
`scripts/openapi-diff.mjs` now receives a real document. The seeded breaking-change proof from `004`
already covers the diff gate.

**Not claimed.**
- The generated client is **not wired into the prototype**. `src/app/App.tsx` is protected and has
  no API calls; `052` consumes `@hivorr/api-client` when it adds the router and providers.
- `openapi:check` cannot validate this uncommitted working tree (`git diff` sees the modified
  client). The in-process contract test is the local proof; CI proves the committed tree.
- The route-coverage test imports controllers and therefore needs Linux/argon2.

## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| Custom zod-backed generator, no `@nestjs/swagger` | No new dependency; zod 4 converts schemas to 2020-12 JSON Schema; the output is deterministic and testable | Yes |
| Request schemas live in `contracts/schemas.ts` | One source for validation and documentation; controllers cannot drift | Yes |
| Explicit response schemas | The spec must describe what the API returns; a generic envelope would be a defect | Yes |
| Generated client is committed | Reviewers see the contract change; CI can diff it | Yes |
| `openapi:check` regenerates and diffs | Catches a stale document or client | Yes |
| Generated client is excluded from `format-check` | Hand-formatting fights the generator; `openapi:check` owns it | Yes |
| Generator excluded from `server/dist` | It is a build tool, not runtime code | Yes |
| Four security schemes, not one | The cookie name differs per audience; one scheme would lie | Yes |
| `healthReady` treats 503 as expected | The readiness probe is designed to report 503; the client should return it, not throw | Yes |
| Route coverage via Nest metadata | Proves the registry and controllers agree without an HTTP server | Yes |
