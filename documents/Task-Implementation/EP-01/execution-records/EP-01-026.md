## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| `withTransaction` as a function plus a `DatabaseService` method | Pure function is testable; the method is the injected entry point | Yes |
| Context is optional | Read-only or setup work may not need it; the service decides | Yes |
| `setIdentity` is callable inside the work | Registration creates ids before the account row exists | Yes |
| Rollback then rethrow the original error | Service mapping (`ApiError`, unique violation) stays intact | Yes |
| Adopt only in grants for now | Proves the helper in a real service without a risky identity rewrite | Yes |
| No repository base class | `030` owns repository extraction; a speculative base would constrain it | Yes |
