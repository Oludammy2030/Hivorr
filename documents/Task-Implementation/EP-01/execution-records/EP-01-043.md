## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| Contract is a committed JSON inventory | Scripts can read it without a TypeScript runtime; review can diff key coverage | Yes |
| Inventory holds no values or defaults | A default silently survives a missing injection | Yes |
| Schema is the key source of truth | `CONFIG_ENV_KEYS` is derived from the actual zod object; the test enforces set equality | Yes |
| Pure policy library | The gate and the tests share one implementation; no duplicated rules | Yes |
| Startup behaviour is tested, not re-implemented | `parseConfig` already fails closed; the test proves it | Yes |
| Client-source scan is name-based | Catches a secret name leaking into bundle source without needing a build | Yes |
| Deployment keys excluded from `.env.example` | A deploy token is not local configuration | Yes |
| Provider change deferred until ruled | It was an open founder/architect decision at implementation time; now resolved to GitHub + Fly | Yes |
