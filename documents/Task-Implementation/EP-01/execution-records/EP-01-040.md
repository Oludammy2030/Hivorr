## 1. Implementation summary

| Area | Result |
|---|---|
| Logger | One-line JSON with timestamp, level, service, environment and event |
| Levels | fatal/error/warn/info/debug/trace/silent; configured filtering |
| Redaction | Recursive, key-based; credentials and personal data |
| Request log | Method, path, status, duration and correlation; no query/headers/body; health skipped |
| Error tracker | Interface plus in-memory capture adapter; no network |
| Filter | `APP_FILTER` with injected logger/tracker; unknown/5xx captured, 4xx not |
| Worker | Structured logger through the existing `OutboxLogger` contract |
| Correlation | Reused `resolveCorrelationId` and the existing header/request hook |

The filter logs only the error name, never the message or stack. The tracker keeps the raw error for
a future vendor adapter without serialising it into a log.

## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| Structured logger as a pure factory with an injectable sink | Testable; no vendor | Yes |
| Key-based recursive redaction | Fast and predictable; no free-text guessing | Yes |
| Error tracker as a seam | Keeps the vendor decision open | Yes |
| Filter via `APP_FILTER` | Enables DI of logger/tracker | Yes |
| Request log path only | Query strings and headers can carry secrets | Yes |
| Worker adapter | Keeps `OutboxLogger` stable while sharing the format | Yes |
| Skip health logs | Avoids probe noise | Yes |
