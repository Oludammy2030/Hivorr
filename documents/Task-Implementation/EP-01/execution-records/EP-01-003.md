## 1. Implementation summary

`@hivorr/shared` now owns every cross-client vocabulary list that previously lived in the server or
existed only in prose:

- **Activities** — the six approved activity IDs from the permission matrix, each with direction,
  dashboard label and approved route family.
- **Capabilities and grants** — the eight capability IDs and six grant IDs moved out of
  `server/src/domain/capabilities.ts`.
- **API errors** — the eight stable error codes and the `ApiErrorBody` shape moved out of
  `server/src/common/errors.ts`.
- **Routes** — 17 approved UI route IDs with portal ownership, path, indexability and authentication
  requirement, derived from `ARCHITECTURE.md` §4.2 and §8.6.
- **Schemas** — zod enums for environments, portals, activities, capabilities, grants, routes and
  error codes; an `ApiErrorBody` object schema.

The server now imports and re-exports the shared types, so no existing import path changed. Capability
**computation** (`computeCapabilities`, `can`) and the `ApiError` class remain server-side, per
`AGENTS.md` Rule 4 (no client authority).

No change was made to the prototype, the theme, the Figma configuration, the permission matrix, the
database rules or the architecture.

## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| `zod` `4.6.7` is added to `packages/shared` at the exact pin already used by `server` | One validation library; the standards pin is preserved. No second validator was introduced. | Yes |
| Capability **computation** stays in `server/src/domain` | Authorisation is a server decision; shipping it to clients would breach Rule 4. Only identifiers and types moved. | Yes |
| The shared error list keeps the existing **eight** codes; `ACTIVITY_INACTIVE` is not added here | The current server cannot emit it. It is added by `011` together with the pipeline guard that emits it, so no unreachable contract value is published. | Yes |
| The `ApiErrorBody` interface is defined once in shared and re-exported by the server | Prevents two structurally identical but independently editable definitions. | Yes |
| Route IDs describe the EP-01 slice, not the prototype's `Screen` union | The prototype union is presentation state, not a URL contract; `052` owns the router. | Yes |
| Activity activation states are exported as vocabulary only | Transitions belong to `033`; exporting the state names now prevents a second literal list later. | Yes |
| `PortalId` is imported into `routes.ts` as a type from `./index` | Type-only import is erased at compile time; no runtime cycle, and no second portal definition. | Yes |
