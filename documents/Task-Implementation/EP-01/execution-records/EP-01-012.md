## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| Grants live under `identity`, not as an eleventh module | §9.2 assigns grants to identity; the module count is ten | Yes |
| Health lives at `server/src/health` | It is infrastructure; a module is a domain boundary | Yes |
| Flat files inside identity rather than layer folders | Moving every file would churn imports and tests without changing a boundary; the linter enforces the rules that matter | Yes |
| `appendAudit(client, entry)` is a function, not an injected service | Callers pass their transaction client; direct service construction in existing tests keeps working | Yes |
| Platform owns `platform.audit_log` | Removes the only cross-schema table write and gives platform a real public surface | Yes |
| Activity modules are index-only with a reviewed `CODE_MODULES` list | The skeleton cannot silently drift into six half-built modules | Yes |
| Linter is regex-based | It targets this repository's import and SQL style; the seeded proofs cover both failure directions | Yes |
| `build:server` cleans `server/dist` | `tsc` leaves files for deleted modules | Yes |
| Filesystem test asserts no activity tables | Makes the EP-01 statement explicit; the owning phase updates it deliberately | Yes |
