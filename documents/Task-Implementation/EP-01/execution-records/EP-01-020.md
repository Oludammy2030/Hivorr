## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| Add `db:check` rather than a startup probe | Connection validation must be runnable by CI and operators without booting the API; readiness remains `026` | Yes |
| Default to no role expectation | CI connects as `postgres`; staging passes `--expect-role hivorr_api` | Yes |
| Require TLS only in staging/production | Local containers and CI have no TLS | Yes |
| Treat unreadable `pg_stat_ssl` as `tls=false` | A remote connection then fails closed rather than claiming TLS | Yes |
| Assert major version in CI | Proves local/CI parity at 17 | Yes |
| Keep the pool's loopback branch | It covers a tunnel or local staging sandbox even though config validation normally refuses it | Yes |
| Document worker variables in `.env.example` | Local worker setup was undocumented | Yes |
