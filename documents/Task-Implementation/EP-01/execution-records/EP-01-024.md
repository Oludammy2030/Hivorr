## 1. Implementation summary

The platform tables already existed from migration `002`. The missing part was the profile module:
one shared profile per account and one activation row per account and activity.

| Area | Result |
|---|---|
| Profile | `profile.profiles`, one row per account, nullable presentation fields |
| Activations | `profile.activity_activations`, unique `(account_id, activity_id)` |
| Activities | Check constraint lists exactly the six shared `ACTIVITY_IDS` |
| States | `INACTIVE`, `ACTIVE`, `RESTRICTED`, `SUSPENDED` |
| Idempotency | The unique constraint makes a second activation a no-op at the database level |
| Identifiers | `platform.uuidv7()` for activation rows |
| Timestamps | `timestamptz` throughout |
| Indexes | `(account_id, state)` and `(activity_id, state)` for RLS and policy filters |
| RLS | Select/insert/update policies on both tables using `platform.current_account_id()` |
| Grants | API write; readonly read; readonly may execute the account policy function |
| Comments | Both tables |
| Platform | Audit, outbox, idempotency, flags and reference counters reused from `002`; no duplicate set |

**Not claimed.** The state transition graph and endpoints belong to `033`; `FORCE ROW LEVEL SECURITY`
and the full allow/deny matrix belong to `025`. `display_name` is nullable until the profile is
edited or activation fills it.

## 3. Architectural and technical decisions

| Decision | Reason | Reversible |
|---|---|---|
| One profile per account, not one per activity | The matrix makes the profile shared; activities differ by state, not by identity | No |
| Unique `(account_id, activity_id)` | Activation is idempotent by construction | No |
| Four-state check now, transitions later | `033` owns the transition graph; constraining the set now prevents typo drift | Yes |
| RLS policies in the same migration | A new table must not exist without RLS (the migration lint enforces this) | No |
| Account/state and activity/state indexes | RLS filters by account; the switcher and policy filter by state | Yes |
| Grant EXECUTE on `current_account_id()` to readonly | A policy expression runs with the querying role; without it, readonly reads fail | Yes |
| No new platform tables | `002` already owns the audit/outbox/idempotency/flag/reference shapes | No |
