## 1. Implementation summary

| Area | Result |
|---|---|
| Write | `appendAudit` stores optional `before_summary` / `after_summary` |
| Registration | After summary with account/user ids |
| Sign-in | After summary with session id, audience and environment |
| Sign-out | Before/after revocation booleans |
| Refresh | After summary with the rotated session |
| Activity | Before/after state on activation and deactivation |
| Grants | Before/after state on create and revoke |
| Read model | `listAuditEntries` returns summaries; the control probe exposes them |
| Immutability | Trigger rejects update and delete; API has no update/delete privilege |
| Failure | An audit insert rejection propagates to the caller's transaction |

Summaries contain identifiers and state only; no token, hash or credential is recorded.
