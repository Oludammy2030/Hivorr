# Staging topology evidence — 2026-11-10

**Task:** `EP-01-060` — environment topology and staging provisioning
**Environment:** live staging, from a read-only probe
**Command:** `pnpm verify:staging-hosts`
**Network:** public HTTPS, no credential, no provider API, no redirect followed

No secret, Access token or connection string is recorded in this file. The Access redirect URL and
its signed `meta` parameter are deliberately omitted.

The API response was:

```json
{"status":"ok","service":"hivorr-api","version":"v1","environment":"staging"}
```

All four hosts resolve through Cloudflare. The three privileged hosts redirect to a
`*.cloudflareaccess.com` sign-in endpoint before any bundle loads.

## What this proves

- DNS resolves for the four recorded staging hosts.
- The certificate covers each host's own name and is currently valid.
- The main host serves the frontend; `/api/v1/health/live` reaches a staging API.
- Cloudflare Access challenges the control, staff and partner hosts.
- The production hosts were not contacted.

## What this does not prove

| Item | State |
|---|---|
| `DATABASE_SSL_CA` certificate verification | Not set; the connection is encrypted but the pooler certificate is not verified (`F-08`). |
| Database, role and credential isolation | Recorded in the runbook and the secret contract; not observable without provider access. |
| Access allowlists | The challenge is observed; who may complete it is a provider-side policy and was not tested. |
| API freshness | **`GET /api/v1/session` and `GET /api/v1/activities` return `404` on staging**, while `POST /api/v1/auth/sign-in` returns a validation error. The staging image predates those routes (`F-49`). |
| Migrations, buckets, Pages project bindings | Recorded in the runbook; not re-verified here. |

`F-49` must be closed by deploying the current release digest (`EP-01-061`) before `EP-01-063`
smoke/E2E can pass.

## Reproduce

```sh
pnpm verify:staging-hosts
```

Exit code 0 means the four hosts, their certificates, the Access challenge and the staging API health
all matched the record.
